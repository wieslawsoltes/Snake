# Validation

## Local reconstruction checks

On 2026-09-15 the version-2 implementation passed:

| Suite | Result | Execution boundary |
| --- | --- | --- |
| Node unit and renderer contracts | 73 passed, 0 failed | Engine, snapshots, collision, storage, bitmap graphics, optical math, uniform layout, fallback and cache/resize contracts |
| Browser gameplay acceptance | 21 passed, 0 failed | Real Chromium DOM/input/layout with the standalone build; explicit fixture storage and Canvas renderer |
| Handset/LCD visual checks | 11 passed, 0 failed | Shell ratio, rectangular-cell projection, receiver geometry, presets, angle control, render settling, mobile target sizes and touch-pad separation |

The local browser host blocks navigation, including localhost. Fixture runs therefore use `page.set_content()` and a deliberately labeled storage adapter. **They do not validate native WebGPU, origin storage, service workers, offline reload or physical mobile hardware.** This limitation is not hidden behind a passing fixture count.

## Repository CI gates

The Pages workflow rebuilds the static site, serves `dist/` through localhost and runs the non-fixture acceptance suites. `tests/browser.py --require-webgpu` must initialize the actual WebGPU backend; falling back does not satisfy this gate. `tests/hosted.py` additionally checks actual WGSL/Canvas projection parity for four presets, real device-loss fallback, service-worker installation and offline gameplay after reload. The software SwiftShader adapter is used for repeatability, not GPU benchmarking.

Generated reports record their own execution mode:

- `unit-test-results.txt`: Node TAP results.
- `browser-test-results.json`: individual checks and `fixture_mode`.
- `fidelity-results.json`: individual appearance/control checks and `fixture`.
- `hosted-test-results.json`: real-origin checks, adapter information and pixel-difference metrics, when successfully executed.
- `CI-VALIDATION.md`: workflow execution/commit record, when generated by a successful CI run.

The presence of a workflow or test script is not itself evidence of a passing remote run. Consult those machine-readable reports and the corresponding GitHub Actions run. Workflow artifacts contain screenshots and reports; Pages deployment is gated on the validation job.

## Remaining physical verification

Physical iOS/Android touch and haptic delivery, accessibility on real VoiceOver/TalkBack devices, color-managed comparison with a specified original Nokia LCD, and hardware-GPU performance are not established by headless CI. The LCD rise/decay constants, lens response and panel color are reconstruction parameters, not measured specifications. See [FIDELITY.md](FIDELITY.md).

## Repeat

```sh
npm test
npm run build
python -m pip install -r requirements-dev.txt
python -m playwright install --with-deps chromium
node tools/serve.mjs dist 8080
# Separate terminal:
python tests/browser.py --require-webgpu
python tests/fidelity.py
python tests/hosted.py
```

For a navigation-restricted host only, use `--fixture` for the first two Python suites. `tests/hosted.py` intentionally provides no fixture mode.
